## 结论

- **安装包：** rc.7 与 1.0.0 安装包都已构建并在本机验证过。安装、升级、同版本重装、两种卸载方式、卸载后重装都按设计完成，没有发现阻塞问题。
- **用户数据：** 生产数据库保留完好，用户设置在每次安装后都恢复了。
- **Claude 设置：** 真实的 settings.json 在测试后逐字节恢复原样。
- **新问题：** 验收中发现两个小问题，记为待办第 55、56 项，都不影响这一版的使用。
- **观察结果：** 期间电脑意外断电或死机一次，又重启一次。1.0.0 两次都由开机自启正常启动，数据库完好，读取失败时按规则发出了一次 "无法刷新" 提醒（§8）。仍有几项没有真实证据，见 §6。

**改版范围的来源：** 本轮 UI 改版依据用户贴来的 GPT 审阅（"批准本轮 UI 改版，但暂时不要把 13 个提醒开关合并成 3 个"）。用户在贴这份文档时没有另写自己的意见，我把它当作批准执行，并在报告中写明。之后用户在 11-03 明确同意 "现在开始全部"，即真实窗口检查和安装验收。

## 4. 本轮新记录的问题（都不阻塞发布）

- **待办 55：** 应用内打开开机自启时，写入的路径没有引号。来自 `tauri-plugin-autostart` / auto-launch，rc.6 及更早已有此行为。路径有空格时通常仍能启动，风险低。
- **待办 56：** 同版本重装会覆盖 `backups\before-<版本>`。这次 `before-1.0.0-rc.7` 被覆盖了两次，因为另有手工备份，没有丢数据。

第二轮独立复查查实的问题（Codex 关了又马上开时刷新误报 "监控已暂停"）已在 `e428940` 修复，并在真实窗口中确认（§2）。第 52–54 项是复查确认但有意留到 1.0 之后的差异。

## 5. 需要说明的取舍

- **透明度：** 用户在使用中的透明度（今天在 50–90% 之间调整过，现在是 55%），低于 85% 时，在与主题明暗相反的背景上，琥珀色和红色的数值达不到 WCAG AA。65% 时约 2.4–2.8:1，50% 时约 1.6–1.9:1。默认 85% 在所测背景上全部达到 4.5:1。设置里有提示，但没有改用户的值。
- **5 小时低余量：** 数值可以显示为红色，同时不发提醒，因为 5 小时提醒默认关闭。
- **托盘图标：** 正常状态为中性灰。动态图标留到 V1.1。
- **提醒开关：** 13 个提醒开关全部保留，按审阅要求没有合并成 3 个（V1.1）。
- **兼容模式：** 概览中 Codex 的 "兼容模式" 按 SPEC 保留为纯文字。
